# Testing and verification

## Standard checks

Install once with `npm install`. The normal full check is:

```powershell
npm test
```

This uses Node's built-in test runner. Tests start the exported HTTP/Socket.IO server on an ephemeral port, clear the global ticker, close Socket.IO, and close the server during teardown.

Also run:

```powershell
git diff --check
```

Asset changes additionally require:

```powershell
npm run assets:generate
npm run assets:check
```

The generator is deterministic and the validator compares every committed generated byte; validates the manifest schema, explicit per-sprite 2x/3x/4x logical scale, uniform nearest-neighbor pixel blocks, 8-bit RGBA PNG dimensions, atlas and sprite-region hashes, opaque pixels, and non-overlapping sprite rectangles; rejects missing/orphan files and blank/duplicate portraits; proves exact 29-card, 2-weapon, 6-structure, 10-effect-family, and four lifecycle-sprite coverage; and enforces the 1024px atlas, 300KB critical, and 500KB optional ceilings. `test/assets.test.js` covers determinism, coarse-grid metadata and block alignment, minimum central-glyph separation across all card pairs, result/status sprite uniqueness, and deliberate missing/orphan failures.

Live browser changes additionally require:

```powershell
npm run test:browser
```

This launches installed Microsoft Edge through `playwright-core` with software compositing for stable captures, starts the exported server on an ephemeral port, and uses a shared 320x700, 390x600 short-height, 390x844, 720x900 shell, and 1440x900 matrix for lobby, Deck, battle, search, representative result, and leave states. A separate 320-CSS-pixel fixture at 2x device scale and reduced motion exercises lobby, Deck, battle, leave, and result surfaces; it is an automated effective-narrow/raster-scale proxy, not a claim that device scale equals browser zoom. Keep real 200% browser zoom as a manual accessibility check and report explicitly when the active browser surface cannot expose or verify its zoom level.

The browser gate checks nonempty 48px targets, clipping, visible dark/gold focus, HTTP/console/network cleanliness, same-origin initial loading, manifest fetch plus decode/dimension checks for every atlas, every generated sprite class, and exact 29-card/2-weapon/6-structure/10-family registry coverage. It renders Fortify, Clash, Overload, and Double Taps; both weapons; all six structures; Shielded and broken defenses; every lane; one representative from every effect family; staged, pending, siphon, queue, dialog, and all result paths. Accessibility assertions cover the rival reserve progressbar, named structure lists/listitems, declared `I`/F2 inspection, focusable aria-disabled weapon/pending-card inspection with guarded activation, inactive/counterable rival targets, single live announcements, dialog inertness/focus containment/restoration, keyboard-only deployment/inspection/siphoning, reduced-motion siphon/deployment/effect/result equivalence, and non-color states.

The 100ms-path gate warms one snapshot, renders it 500 times, requires an average below 5ms, allows at most four mutation records, and requires stable hand/structure roots, identical node count, and no effect/flight creation. Ten screen transitions and ten Deck visits must preserve public Socket.IO listener counts and stable roots without accumulating DOM; effect nodes remain capped at 18 and the completed workflow leaves fewer than 1,200 nodes with one of each overlay. Deck migration, details/toggle/filter, draft, focus/scroll, transactional storage-failure, queue-cancellation, exact-order/weapon persistence, CPU/two-window online, lifecycle progression/rematch, and bounded particle checks remain part of the same command. Captures go to ignored `artifacts/browser/`.

Use `npm start` for manual browser verification at `http://localhost:3000`; `npm run dev` restarts Node on server changes.

- phase escalation, Overload pressure, and Double Taps at 180 seconds

- six-unique-card loadout validation, three-card hands, staged blank slots, swaps, and bottom-of-cycle rotation
- bounded ordered presentation events, legacy `lastEvent` compatibility, same-tick resolutions, exact Shield/Wall/core damage routing, and authoritative heal/Shield/self-damage outcomes
- three-hit siphon bursts at the cumulative two-for-one removal rate
- one staged card per category, first-tap locking, counterplay unlocking, and Attack sharing with the permanent weapon
- Wall destruction leaving tap reserves unchanged
- the eight-structure limit and valid card categories/catalogue size
- online pairing and synchronized authoritative commitments
- CPU use of the same starting taps and visible resource model

`test/lifecycle.test.js` verifies:

- `cancelSearch` removes a waiting socket and `startCpu` interrupts an active online search
- leave emits identical, exact `{ winner, reason, state }` payloads to both connected players after the final state
- disconnect emits the same exact terminal shape to the survivor after the final state
- both leave and disconnect remove the old match and permit a clean online rematch with fresh core, taps, stats, and match ID

`test/agent-context.test.js` keeps the root agent map under 100 lines and fails when a required routed context file is missing or no longer named in the map.

`test/frontend.test.js` guards the presentation-only shared frame for cards and weapons, catalogue sprite integration, stable delegated Deck contracts, strict draft/save validation, details/order/source hooks, lifecycle focus/authority/cleanup contracts, non-result interruption, bounded result feedback, metadata-driven family renderer, bounded battle effects, event replay protection, local assets, keyboard counterplay, guarded hot-render helpers, focus/reduced-motion release CSS, and retired-proof cleanup.

`test/catalogue.test.js` pins the approved display name and short-label mapping for all 29 stable card keys while preserving Cannon and Volley.

Keep direct function tests deterministic by passing explicit timestamps. Use Socket.IO integration tests for queueing, room broadcasts, connection lifecycle, and client/server payload behavior.

## Verification by change type

| Change | Minimum verification |
| --- | --- |
| Server rule, timing, resource, card effect, or bot logic | Focused direct test plus full `npm test` |
| Socket event or public state shape | Integration test plus full `npm test` |
| Card/category/weapon data | Validation/effect test, builder inspection, full `npm test` |
| Hand deployment, swapping, lane disabling, queued-card tap input, or right-click inspection | Existing source contract test, manual left/right-click pass while state updates, confirm right-click spends nothing, verify blocked controls remain keyboard-inspectable but cannot activate |
| Battlefield layout or cues | Phone-width and desktop-width visual inspection, both weapons, active/pending/siphon states |
| Accessibility | Keyboard-only pass, 200% zoom/narrow reflow, focus visibility, reduced motion, live status behavior |
| Queue, leave, result, disconnect, or rematch lifecycle | Focused Socket.IO lifecycle test, phone/desktop and reduced-motion browser workflow, progression/focus/cleanup assertions, full `npm test` |
| Documentation/context only | Link/path check, `git diff --check`, and `npm test` when instructions describe testable behavior |

## Manual battle smoke pass

1. Start a CPU match and confirm both sides begin with 10 taps.
2. Deploy cards from the three-card hand and confirm each flies to the correct battlefield category while its original slot becomes an outlined blank.
3. Stage one card in every category, then tap each battlefield card independently. Confirm only the tapped category locks with a readable busy label.
4. Swap an untouched staged card for a same-category hand card; confirm the old card returns and the new card's original slot becomes blank.
5. Confirm only the chosen weapon appears, Crew animates in the center, Magic animates on the right, and structures fill no more than eight slots.
6. Siphon each enemy zone, checking pips, retreating progress, reserve transfer, and swap availability at zero.
7. Let a card complete and verify its reserved blank fills immediately, the next-card label advances, and the completed card rotates.
8. Break a Wall and confirm neither player's taps jump.
9. Right-click a hand card, staged card, weapon, and visible rival card. Confirm each shows concise stats and spends no tap or progress; confirm left-click still immediately performs its normal action.

If a check cannot be run, state exactly which check and why. Do not silently treat static source inspection as runtime verification.
