## Delivered lifecycle

- Search for Battle exposes idle, searching/cancel, and offline states through visible copy, deterministic status sprites, `aria-pressed`, `aria-busy`, and concise lifecycle announcements. Canceling search or switching to CPU removes the socket from the global queue.
- Leave Battle opens an explicit confirmation. Stay receives initial focus; Tab/Shift+Tab remain inside; Escape or the backdrop cancels and restores focus; confirm is guarded against duplicate emission, sends `leaveMatch`, and returns to the lobby.
- Victory, defeat, stalemate, rival forfeit, rival disconnect, and local connection interruption have non-color state, distinct reason copy, a local emblem, final core values, performance statistics, and a tactical read.
- Opening either lifecycle dialog makes the app shell inert and hidden from assistive technology, clears toast and inspector overlays, and places focus deliberately. Closing restores interaction and either returns focus or moves it to the next screen's primary control.
- Result decoration is bounded to six particles for victory and four for defeat/draw, clears after one second, and is absent for local interruption and reduced motion. Toast, inspector, confirmation, and result layers have an explicit stacking order.
- CPU Run It Back creates a fresh CPU match. Online Run It Back leaves the completed match and begins a fresh global search. Lobby return never attempts to resume terminal state.
- Sound keeps a stable accessible name with pressed state and on/off imagery. Challenges remains visibly disabled, `aria-disabled`, and labeled Locked.

## Authority and progression

- Server `finish()` emits the final serialized state before the exact `{ winner, reason, state }` `gameOver` payload and deletes the ended match. Winners remain sides `1`/`2`, with `0` for a simultaneous core draw; reasons remain `core`, `leave`, and `disconnect`.
- Voluntary leave awards the other side and reaches both connected sockets. Disconnect awards the survivor; the disconnected socket cannot receive its own terminal event.
- The client consumes one matching authoritative terminal event. A recorded result increments duels once; victory increments wins and streak, defeat resets streak, and draw preserves streak. Duplicate or stale payloads do not change progression twice.
- A local transport interruption is deliberately a non-result. It records no duel, win, loss, or streak change, cannot resume the abandoned battle, and allows a fresh battle only after reconnection.
- Server authority, event names, result payload shape, match rules, six-card saved-loadout contract, three-card battle hand, Phase 3 presentation schema, and all Phase 4 display names remain unchanged.

## Preserved decisions, deviations, and limitations

- There is no pause, resume, private rematch room, reconnect recovery, settings screen, or implemented Challenges surface. Phase 6 does not infer any of those features from lifecycle styling.
- A local disconnect cannot be reported as an authoritative defeat because that socket cannot receive its own disconnect event. The UI explicitly labels it an interrupted, unrecorded match; the connected opponent still receives the server-awarded victory.
- Online rematch is intentionally a new global search, not a promise to pair the same players. CPU rematch is a clean match with fresh server state.
- Result particles are presentation-only and never stand in for outcome text, emblem, reason, or live announcement.
- Phase 7 completed the repository-wide effective-narrow/manual keyboard audit, performance measurements, stale-selector/style cleanup, and release regression pass; see `PHASE_07_HANDOFF.md`.
